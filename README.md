# Veil

Туннель. Снаружи соединение выглядит как обычный HTTPS. Клиент поднимает локальный SOCKS5 и HTTP-прокси: программа ходит в сеть, если ей указан этот прокси.

Один бинарник `veil` — и сервер, и клиент.

## Сборка

Нужен Go версии из `go.mod` или новее. Из корня репозитория в PowerShell:

```powershell
.\build.ps1
```

Скрипт кладёт файлы в `dist/`:

- `veil-windows-amd64.exe`
- `veil-linux-amd64`
- `veil-linux-arm64`
- `veil-darwin-amd64`
- `veil-darwin-arm64`

Только для текущей системы:

```powershell
go build -trimpath -ldflags "-s -w" -o veil.exe ./cmd/veil
```

## Сервер

Нужен свой домен и сертификат, которому доверяет система. Готовые `cert.pem` и `key.pem` положите в каталог из `VEIL_CERT_DIR`. В `.env.example` это `./certs`.

Либо сервер сам получит сертификат Let's Encrypt. Нужны домен, свободный порт 80 и явное согласие с условиями центра:

```powershell
.\dist\veil-windows-amd64.exe serve -listen :443 -acme-domain пример.com -acme-accept -keys keys
```

`-acme-accept` обязателен: без него сервер с `-acme-domain` не запускается. Проверка домена слушает `-acme-http` (по умолчанию `:80`). Кэш лежит в `-acme-cache` (по умолчанию каталог `autocert` рядом с процессом). Пока `-acme-domain` не задан, сервер по-прежнему берёт только `-cert` и `-key`.

Секрет — отдельный ключ на человека. `keygen` печатает одну строку base64:

```powershell
.\dist\veil-windows-amd64.exe keygen
```

Один общий ключ по-прежнему передаётся в `-psk`. Список людей — файл, одна строка на ключ. Пустые строки и строки с `#` не считаются.

```powershell
.\dist\veil-windows-amd64.exe serve -listen :443 -cert cert.pem -key key.pem -psk КЛЮЧ -keys keys
```

Можно указать только `-psk`, только `-keys` или оба сразу. Нет ни одного ключа — сервер не стартует. Страница, которую видит чужой запрос, считается от первого ключа: сначала `-psk`, потом файл. Если файл изменился, сервер перечитывает его сам, перезапуск не нужен.

Отозвать доступ — убрать строку из файла:

```powershell
.\dist\veil-windows-amd64.exe revoke -keys keys -psk КЛЮЧ
```

Этой команды достаточно: сервер замечает новое время файла. Сам ключ в журнал не пишется. Клиент по-прежнему хранит один свой ключ в `-psk`, JSON или `veil://`.

Скопируйте `.env.example` в `.env`. `VEIL_PSK` — один ключ, `VEIL_KEYS` — путь к файлу внутри контейнера. `VEIL_PORT` — порт на машине, где запущен Docker (по умолчанию 443).

```powershell
docker compose up -d --build
```

Compose собирает образ из `Dockerfile`, публикует `${VEIL_PORT}:443` и порт 80 для проверки сертификата, монтирует каталог сертификатов в `/etc/veil` только для чтения и том кэша ACME. Без домена контейнер по-прежнему ждёт `cert.pem` и `key.pem` и ключ (`VEIL_PSK` или `VEIL_KEYS`). Если заданы `VEIL_ACME_DOMAIN` и `VEIL_ACME_ACCEPT=1`, PEM не нужен. Файл ключей с хоста кладётся в каталог `VEIL_KEYS_DIR` (по умолчанию `./keys`) и в контейнере доступен как `/etc/veil/keys/`.

Без Docker на Linux-сервере:

```sh
./veil-linux-amd64 serve -listen :443 -cert cert.pem -key key.pem -psk КЛЮЧ
```

Для `linux/arm64` берите `veil-linux-arm64`.

## Клиент

```powershell
.\dist\veil-windows-amd64.exe connect -server домен:443 -psk КЛЮЧ
```

В программе укажите SOCKS5 `127.0.0.1:1080`. Если имя в сертификате другое, чем адрес в `-server`, добавьте `-sni ИМЯ`.

Рядом поднимается HTTP-прокси `127.0.0.1:8080`. Его можно указать в браузере или в системе: адрес `127.0.0.1`, порт `8080`. В Windows это «Параметры → Сеть и Интернет → Прокси → Использовать прокси-сервер». `-http -` выключает HTTP-прокси, SOCKS5 остаётся на `127.0.0.1:1080`.

Программа сама не меняет системный прокси и DNS и не забирает трафик программ, которым прокси не указан.

Локальный DNS по умолчанию выключен. Он только пересылает запросы в туннель и не подменяет их ответом системного резолвера.

```powershell
.\dist\veil-windows-amd64.exe connect -server домен:443 -psk КЛЮЧ -dns 127.0.0.1:5353
```

Укажите резолверу адрес `127.0.0.1:5353`. Встроенная настройка DNS Windows шлёт запросы на порт 53, поэтому для неё нужен `-dns 127.0.0.1:53` (запуск от администратора). Иначе оставьте `5353` и направьте туда программу, которая умеет порт.

Те же параметры можно держать в JSON и не набирать флаги каждый раз:

```powershell
.\dist\veil-windows-amd64.exe connect -config client.json
```

```json
{
  "server": "домен:443",
  "psk": "КЛЮЧ",
  "sni": "имя",
  "listen": "127.0.0.1:1080",
  "httpListen": "127.0.0.1:8080",
  "dns": "127.0.0.1:5353",
  "insecure": false
}
```

Обязательны `server` и `psk`. Строка `psk` та же, что у флага `-psk`. Лишние поля пропускаются. Флаг, который указали в команде, перекрывает поле из файла или ссылки. Если `-listen` не передали и в файле его нет, остаётся `127.0.0.1:1080`. Если нет `-http` и в файле нет `httpListen`, остаётся `127.0.0.1:8080`. Пустой `dns` значит, что локальный DNS выключен; `"httpListen": "-"` выключает HTTP-прокси.

Короткая ссылка — тот же JSON в raw base64url, схема `veil://`. В ссылку не входят `listen`, `httpListen` и `dns`: это адреса на своей машине. Команда печатает одну строку в stdout.

```powershell
.\dist\veil-windows-amd64.exe link -server домен:443 -psk КЛЮЧ -sni имя
.\dist\veil-windows-amd64.exe connect -url veil://...
```

`-config` и `-url` вместе указать нельзя.

Двойной щелчок по `veil.exe` в Windows ищет `client.json` в той же папке, что и программа, и подключается. Консоль при этом закрывается, остаётся значок в трее. Если файла рядом нет, появляется окно с этой причиной. Запуск из PowerShell без команды по-прежнему печатает справку и сразу завершается.

Перед приёмом соединений клиент один раз проверяет сервер. Если связи нет, в консоли одна фраза: сервер не ответил, сертификат не принят, ключ не подошёл или нет связи. На Windows по умолчанию в области уведомлений висит значок с этой фразой и пунктом «Выход». `-tray=false` выключает значок: при неудачной проверке `connect` сразу завершается. На других системах значок не создаётся.

Автозапуск есть только в Windows и только из файла настроек, чтобы ключ не попал в реестр:

```powershell
.\dist\veil-windows-amd64.exe autostart on -config C:\path\client.json
.\dist\veil-windows-amd64.exe autostart off
```

В реестр пишется путь к программе и `connect -config` с абсолютным путём файла. `-psk` и `-url` для автозапуска не используются.

## Лаборатория

Это проверка на своей машине, а не обход блокировок. `veil cert` пишет самоподписанный сертификат. Клиент тогда запускают с `-insecure`: сертификат не проверяется.

```powershell
.\dist\veil-windows-amd64.exe cert -host ИМЯ -cert cert.pem -key key.pem
.\dist\veil-windows-amd64.exe serve -listen :443 -cert cert.pem -key key.pem -psk КЛЮЧ
.\dist\veil-windows-amd64.exe connect -server 127.0.0.1:443 -sni ИМЯ -psk КЛЮЧ -insecure
```

`cert` не перезаписывает уже существующие `cert.pem` и `key.pem`. Сервер из `serve` не соединяется с loopback, link-local, multicast и неопределённым адресом: через SOCKS5 открывайте внешний адрес.
