# Протокол Veil, версия 1

Документ описывает байты на проводе так, как их пишет текущий код в `internal/proto`, `internal/client` и `internal/server`. Это контракт между клиентом и сервером.

## Модель

```text
приложение
   │  SOCKS5 CONNECT
   ▼
клиент Veil
   │  TCP + TLS (ClientHello как у Chrome) + HTTP/2 POST
   ▼
сервер Veil
   │  обычный TCP к адресу из кадра Dial
   ▼
сайт или другой хост
```

Фильтр, который не расшифровывает TLS, видит сессию HTTPS. Фильтр, который подключается сам и говорит HTTP, получает HTML-страницу. Туннель открывается только при знании PSK.

Один POST несёт одно TCP-соединение назначения. Несколько SOCKS-сессий — несколько POST на одном TLS-соединении HTTP/2. Мультиплексирования нескольких целей внутри одного POST нет.

Часы клиента и сервера расходятся не больше чем на 120 секунд.

## Транспорт

1. Клиент открывает TCP на `host:port` из `-server`. Если порта нет, подставляется 443.
2. TLS-клиент — `utls.HelloChrome_Auto`. SNI берётся из `-sni`, иначе из имени в `-server`. Проверка сертификата обычная; `-insecure` отключает её и годится только для лаборатории.
3. Согласованный ALPN — `h2`. Иначе клиент закрывает соединение.
4. Клиент шлёт `POST /` без известной длины тела (`ContentLength = -1`). Заголовки: `Content-Type: application/octet-stream`, `Accept: */*`, User-Agent Chrome. Редиректы не следуются.
5. Сервер принимает TLS 1.2 и новее, ALPN `h2` и `http/1.1`. Сертификат — тот, что передан в `serve`. Для обхода нужен сертификат, которому доверяет система, на имя из SNI.

На свободном соединении клиент шлёт HTTP/2 PING после 30 секунд тишины и ждёт PONG 15 секунд. Это удержание NAT, а не часть Veil.

## Два ответа сервера

Пока сервер не вызвал `WriteHeader`, любой сбой — это страница.

| Условие | Ответ |
| --- | --- |
| Не POST, короткий или битый hello, неверный PSK, повтор nonce, плохой ключ | `200`, `text/html; charset=utf-8`, `Cache-Control: public, max-age=300`, тело страницы |
| Hello принят | `200`, `application/octet-stream`, `Cache-Control: no-store`, дальше байты сессии |

Сервер принимает hello на любом из настроенных ключей. Байты hello те же: та же раскладка и те же строки HKDF, `version` остаётся 1. Страница одна на процесс и считается от первого ключа в списке сервера (сначала ключ `-psk`, затем файл): seed = `SHA-256("veil-v1-page" \|\| psk)`. Перебор ключей в HTML не виден. В тексте страницы нет слова veil и нет внешних ресурсов. Различие успешного входа и зонда — `Content-Type`, не код статуса.

Чтение hello ограничено 10 секундами. После успеха дедлайн снимается.

## Рукопожатие

Все многобайтовые целые — big-endian. Длины и смещения ниже в байтах.

Общий вид hello, в обе стороны:

```text
nonce          24
sealed_len     u16
sealed         sealed_len
```

`sealed` — XChaCha20-Poly1305. Нонс — случайные 24 байта в начале сообщения, они же нонс AEAD. Дополнительных данных (AAD) у hello нет. `sealed_len` от `Overhead` до `512 + Overhead`. Большая длина отвергается до чтения хвоста.

Ключ hello, 32 байта:

```text
HKDF-SHA256(secret = PSK, salt = пусто, info = ..., length = 32)
```

| Направление | info |
| --- | --- |
| клиент → сервер | `veil-v1-hello-c2s` |
| сервер → клиент | `veil-v1-hello-s2c` |

Открытый текст hello клиента, затем 0–200 нулевых байт дополнения. Длина дополнения случайна.

```text
version        u8 = 1
unix_seconds   u64
x25519_pub     32
pad            0..200
```

Открытый текст hello сервера:

```text
version        u8 = 1
unix_seconds   u64
x25519_pub     32
client_nonce   24
pad            0..200
```

`client_nonce` — те же 24 байта, что стояли в заголовке клиентского hello. Клиент сравнивает их в постоянном времени и отвергает чужой ответ.

Проверки сервера, по порядку: открытие AEAD, `version == 1`, `|now - unix_seconds| <= 120s`, публичный ключ принимается X25519, общий секрет не нулевой, nonce ещё не видели. Успешный nonce помнится 4 минуты. Повтор отвергается и выглядит как обычная страница.

Ключи эфемерные на каждый POST. PSK только аутентифицирует hello и входит в соль сессии.

## Ключи сессии

```text
shared = X25519(client_eph, server_eph)
salt   = PSK || client_pub || server_pub || client_nonce || server_nonce
c2s    = HKDF-SHA256(secret = shared, salt = salt, info = "veil-v1-c2s", length = 32)
s2c    = HKDF-SHA256(secret = shared, salt = salt, info = "veil-v1-s2c", length = 32)
```

Оба ключа — ChaCha20-Poly1305 с 12-байтовым нонсом. Нонс = 4 нулевых байта и счётчик `u64` с нуля, отдельный для каждого направления. Счётчик в пакет не пишется. Повтор нонса не допускается.

Клиент шифрует на `c2s` и читает `s2c`. Сервер наоборот.

## Кадры

После hello в ту же сторону идут только кадры. Сервер пишет свой hello в тело ответа и дальше читает кадры клиента.

```text
sealed_len     u16
sealed         sealed_len
```

AAD шифрования — два байта `sealed_len`. Открытый текст:

```text
type           u8
pad_len        u16
payload        остаток минус pad_len
pad            pad_len нулевых байт
```

`pad_len` от 0 до 512 включительно. Полезная нагрузка не длиннее 16384 байт. Кадр длиннее `3 + 16384 + 512 + Overhead` отвергается.

| type | Имя | Кто шлёт | Полезная нагрузка |
| --- | --- | --- | --- |
| 1 | Dial | клиент | адрес, см. ниже |
| 2 | DialOK | сервер | пусто |
| 3 | DialErr | сервер | пусто |
| 4 | Data | обе стороны | байты TCP |
| 5 | Close | обе стороны | пусто |

Первый кадр клиента — `Dial`. Сервер ждёт его не дольше 30 секунд, затем дедлайн чтения снимает. Иной первый кадр завершает POST без страницы: заголовки уже отправлены. `DialErr` означает, что SOCKS-клиенту нужно ответить отказом. Успешный SOCKS-ответ пишется только после `DialOK`.

Новый тип получает номер 6 и дальше, явным значением. Уже выданные номера не сдвигаются.

## Адрес в Dial

```text
atyp = 1    IPv4:  4 байта + port u16          всего 7
atyp = 4    IPv6:  16 байт + port u16          всего 19
atyp = 3    имя:   u8 длина, 1..255 байт, port всего 2 + длина + 2
```

Порт 0 запрещён. Пробел и перевод строки в имени запрещены. Домен сервер резолвит сам и соединяется с конкретным IP после проверки. Запрещены multicast, unspecified, link-local (включая 169.254.169.254) и по умолчанию loopback. Частные сети RFC 1918 разрешены. Если ни один адрес не подошёл, клиент получает `DialErr`.

## Порядок одной сессии

```text
клиент                         сервер                         цель
  | POST + client hello            |                              |
  |------------------------------->|                              |
  |                                | страница, если hello плохой  |
  |     server hello (octet-stream)|                              |
  |<-------------------------------|                              |
  | Dial                           |                              |
  |------------------------------->| TCP connect                  |
  |                                |----------------------------->|
  | DialOK либо DialErr            |                              |
  |<-------------------------------|                              |
  | Data / Close                   | Data / Close                 |
  |<------------------------------>|<---------------------------->|
```

`Close` в одну сторону вызывает `CloseWrite` на локальном TCP. Вторая сторона ещё читает и может слать `Data`, пока не пришлёт свой `Close`. Ошибка чтения или записи рвёт обе стороны.

Запись кадров одного потока сериализована. Читает кадры одна горутина. `Stream.Close` закрывает нижележащие тела HTTP один раз и тем разблокирует чтение.

## SOCKS5

Клиент слушает по умолчанию `127.0.0.1:1080`.

- Принимается только версия 5 и метод без аутентификации (`0x00`). Иначе ответ `0x05 0xFF`.
- Команда только CONNECT (`0x01`). Адрес IPv4, IPv6 или домен.
- Успех: `0x05 0x00 0x00 0x01` и шесть нулевых байт (bind 0.0.0.0:0).
- Отказ: тот же ответ с `REP = 0x01`. Отказ отправляется один раз.

UDP ASSOCIATE нет.

## Совместимость

`version` в открытом тексте hello равен 1. Другое значение — отказ рукопожатия и HTML-страница.

Несколько ключей на сервере версию не поднимают. Клиент по-прежнему хранит один PSK. Ключ, которого нет в списке, получает ту же страницу, что и зонд.

Смена любой из строк HKDF, размера nonce, раскладки hello, AAD кадра или номеров типов — новая версия. Пока сервер не умеет читать обе версии, старый клиент перестаёт входить и получает страницу. Это безопасный отказ: сигнатуры «битого Veil» на проводе не появляется, зонд видит тот же сайт.

Лабораторный сертификат из `veil cert` — ECDSA P-256, срок год, SAN по IP или DNS. На боевом сервере его заменяют сертификатом доверенного центра.
