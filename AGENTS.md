# Veil: как развивать проект

Veil — туннель с приоритетом обхода блокировок. Снаружи соединение выглядит как HTTPS браузера Chrome. Свой протокол начинается только внутри TLS.

Перед сменой формата пакетов прочитай [docs/protocol.md](docs/protocol.md). После любой смены провода обнови этот файл и спецификацию в том же изменении.

## Инварианты

Эти свойства держат обход блокировок. Ломать их ради удобства нельзя.

- Первые байты сессии случайны и зависят от PSK. Общей магической строки, пути или заголовка, одинаковых у всех установок, нет.
- ClientHello собирает `utls.HelloChrome_Auto`. В `utls.Config` не задаётся `NextProtos`: список ALPN берётся из отпечатка Chrome.
- TCP-адрес (`ServerAddr`) и имя сертификата (`SNI`) задаются раздельно. `dialTLS` игнорирует адрес, который подставил `http2`, и подключается к `ServerAddr`.
- Чужой или битый запрос получает ту же HTML-страницу, статус 200 и `Content-Type: text/html`. Ошибка ключа, повтор nonce и обычный GET выглядят одинаково. `accept` возвращает `false` только до `WriteHeader`. После записи заголовков туннеля обработчик возвращает `true`, иначе страница допишется вторым ответом.
- Страница камуфляжа строится из `SHA-256("veil-v1-page" || psk)` и не содержит слова veil. У разных PSK разный HTML.
- Один HTTP/2 POST — один TCP-адрес назначения. Тело запроса и тело ответа идут одновременно. `Request.ContentLength` остаётся `-1`. Сервер сбрасывает каждый кадр через `http.ResponseController.Flush`.
- У `http.Server` нет `ReadTimeout` и `WriteTimeout`. Любой общий таймаут оборвёт долгий туннель. Короткий дедлайн ставится только на чтение рукопожатия (10 с) и первого кадра `Dial` (30 с), затем снимается нулевым временем.
- `FrameClose` закрывает запись (`CloseWrite`), как TCP FIN. Ответ в обратную сторону ещё может идти.
- Пока CLI явно не включил иное, сервер не соединяется с loopback, link-local, multicast и unspecified. `AllowLoopback` существует для теста и в `serve` не выставляется.
- PSK — 32 байта. Это единственная аутентификация.
- Комментарии в коде только там, где без них неочевидно зачем. Новые комментарии — на русском.

## Карта кода

| Путь | Роль |
| --- | --- |
| `cmd/veil` | Команды `keygen`, `cert`, `serve`, `connect`. Сюда не класть протокол. |
| `internal/proto` | Рукопожатие, ключи, кадры, кодирование адреса. Единственное место формата провода. |
| `internal/client` | SOCKS5, uTLS, HTTP/2 POST, порядок кадров клиента. |
| `internal/server` | TLS, камуфляж, проверка входа, DNS и запрет адресов, порядок кадров сервера. |
| `internal/relay` | Двустороннее копирование после `DialOK`. |
| `internal/socks5` | Разбор SOCKS5 CONNECT без аутентификации. |
| `internal/tlsutil` | Самоподписанный сертификат для лаборатории. Для обхода его не использовать. |
| `internal/server/server_test.go` | Сквозной тест: зонд GET/POST, эхо 20 КБ, отказ на закрытый порт. |

Зависимости: `github.com/refraction-networking/utls` (отпечаток клиента), `golang.org/x/net/http2`, `golang.org/x/crypto/chacha20poly1305`, `crypto/hkdf`, `crypto/ecdh`. Модуль называется `veil`. Версия Go — строка `go` в `go.mod`.

## Куда класть изменение

Новый тип кадра:

1. Добавить константу в `internal/proto` следующим явным значением после `FrameClose` (сейчас 5). Вставка в середину `iota` перенумерует уже выпущенные кадры.
2. Описать байты полезной нагрузки в `docs/protocol.md`.
3. Обработать тип и на клиенте, и на сервере. `relay.Pipe` считает неизвестный кадр ошибкой и рвёт поток. Кадр до начала данных (как `Dial`) обрабатывается в `client.handle` и `server.accept`, а не в `relay`.

Новый локальный вход (TUN, HTTP-прокси):

- Новый пакет рядом с `internal/socks5`. Общий кусок — открытие `proto.Stream` из `client.open`.
- SOCKS5 остаётся рабочим. `internal/socks5` понимает только метод `0x00` и команду CONNECT.

Другой внешний транспорт (QUIC, WebSocket):

- Меняется оболочка вокруг `proto.Stream`, а не содержимое кадров.
- Рукопожатие Veil по-прежнему первые байты потока приложения. Статическая сигнатура до них не добавляется.
- Клиентский TLS по-прежнему выглядит как Chrome. Сервер для активного зонда по-прежнему отвечает страницей.

Смена отпечатка:

- Только `client.dialTLS` и адаптер `utlsConn`. Адаптер нужен, потому что `http2` читает `ConnectionState() crypto/tls.ConnectionState`, а uTLS возвращает свой тип.
- После смены отпечатка прогнать `TestProbeAndTunnel`: он устанавливает реальное рукопожатие Chrome против сервера Go.

## Чего не делать втихую

- Не ставить на сервер `ReadTimeout` / `WriteTimeout`.
- Не читать всё тело POST до ответа сервера. Клиент пишет рукопожатие в `io.Pipe` из отдельной горутины и блокируется, пока его не прочитают.
- Не логировать на сервере каждый успешный адрес назначения. Ошибка `dial` уже содержит адрес внутри текста `net.Dial`.
- Не включать `AllowLoopback` в команде `serve`.
- Не подменять сертификат чужого сайта и не проксировать зонды на чужой домен.
- Не менять строки HKDF (`veil-v1-hello-c2s`, `veil-v1-hello-s2c`, `veil-v1-c2s`, `veil-v1-s2c`) и раскладку байтов без смены `version` и записи в спецификации. Старый клиент при несовпадении просто получает HTML.

## Проверка

```powershell
go test ./...
go test -race -count=1 ./...
go build -o veil.exe ./cmd/veil
```

`internal/proto` тестируется без сети. Сквозной тест поднимает локальный TLS и ходит через SOCKS5; ему нужны `AllowLoopback` и `Insecure`. Новый формат кадра или рукопожатия сопровождается тестом в `internal/proto`. Новый порядок запрос/ответ — расширением `TestProbeAndTunnel` либо отдельным тестом, который проверяет и успешный туннель, и ответ-страницу на мусорный POST.

## Стиль

Идентификаторы на английском, тексты CLI и ошибки для пользователя на русском. Пакет делает одну вещь. Общую функцию выносить на втором реальном повторении, а не заранее. `gofmt` обязателен.
